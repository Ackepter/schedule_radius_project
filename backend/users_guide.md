# Руководство по управлению пользователями

Авторизация в системе: вход по логину и паролю, server-side сессии (HttpOnly cookie).
**Публичной регистрации нет** — пользователей создаёт только владелец приложения
через CLI внутри контейнера backend.

## Быстрый старт

Все команды выполняются **внутри контейнера backend**:

```bash
docker compose exec backend python -m app.cli <команда> [аргументы]
```

Проверить, что CLI доступен:

```bash
docker compose exec backend python -m app.cli --help
```

Если пишете команды в PowerShell — синтаксис тот же, кавычки `'...'` менять не нужно.
Для локальной разработки без Docker вместо `docker compose exec backend python ...`
используйте активированное виртуальное окружение:

```powershell
cd backend
.\.venv\Scripts\python.exe -m app.cli <команда> [аргументы]
```

## Создание пользователя

### Интерактивно (рекомендуется)

```bash
docker compose exec backend python -m app.cli create-user
```

Команда спросит имя пользователя и пароль (пароль вводится скрытно, дважды для
подтверждения).

### В одну строку

```bash
docker compose exec backend python -m app.cli create-user \
  --username admin \
  --password 'сложный-пароль'
```

Требования:
- **Имя пользователя**: 3–100 символов, только латинские буквы, цифры, `_`, `-`, `.`.
- **Пароль**: не менее 8 символов.

При успехе выводится:
```
Пользователь «admin» создан (id=1).
```

> Пароль нигде не логируется и не сохраняется в открытом виде — в базе только
> Argon2id-хэш. Свой пароль запомните или сохраните в менеджере паролей.

Первым действием после развёртывания создайте пользователя и сразу войдите.
**Пока не создан ни один пользователь — вход в систему невозможен.**

## Просмотр пользователей

Готового интерфейса во веб-части нет — список смотрится через CLI:

```bash
docker compose exec backend python -m app.cli list-users
```

Пример вывода:

```
Всего пользователей: 2
ID   Статус    Имя пользователя         Создан
------------------------------------------------------------
1    активен   admin                    2026-09-23 10:02
2    активен   teacher1                 2026-09-23 10:15
```

- **Статус** — `активен` / `отключен` (`is_active`).
- Пароли в списке не показываются (никогда — ни здесь, ни через API).

## Удаление пользователя

```bash
docker compose exec backend python -m app.cli delete-user --username <имя>
```

Команда спросит подтверждение: нужно ввести имя пользователя ещё раз.

Для автоматизации (например, в скриптах) подтверждение можно отключить:

```bash
docker compose exec backend python -m app.cli delete-user --username <имя> --yes
```

Что происходит при удалении:
- пользователь удаляется из базы вместе со **всеми его сессиями** —
  существующие входы (если он был залогинен) сразу перестают работать;
- бизнес-данные (ученики, расписания и т.д.) не затрагиваются.

**Ограничение:** нельзя удалить последнего активного пользователя — приложение
должно остаться с возможностью входа. Удаление такого пользователя вернёт ошибку:
```
Ошибка: Нельзя удалить последнего активного пользователя — приложение останется без возможности входа.
```

## Безопасность

- Пароли хранятся только как **Argon2id-хэши** (`argon2-cffi`); plaintext не
  сохраняется и не передаётся.
- Сессии server-side: в cookie — случайный токен (HttpOnly, SameSite=Lax,
  TTL по умолчанию 24 ч), в базе — только SHA-256 токена. Выход (`logout`)
  инвалидирует сессию на сервере.
- Все API-эндпоинты (`/api/*`), кроме `login`/`logout`/`me` и `/health`,
  требуют авторизации → без неё `401`.
- Вход защищён от перебора: **5 неудачных попыток за 15 минут** блокируют
  логин (по IP и имени пользователя), ответ всегда одинаковый
  «Неверное имя пользователя или пароль».
- Параметры сессии и лимитов задаются в `.env` — см.
  [README.md](README.md) → «Переменные окружения (.env)».

## Частые вопросы

**Можно ли создать пользователя из интерфейса сайта?**
Нет, намеренно. Публичной регистрации нет — только владелец через CLI.

**Где лежат пользователи в базе?**
В таблице `users` (логин, хэш пароля, `is_active`), сессии — в таблице `sessions`.

**Пользователь забыл пароль. Что делать?**
Удалить пользователя (`delete-user`) и создать заново с новым паролем.
Сменить пароль без удаления пока нельзя.

**Заблокировали за слишком много неудачных входов, что делать?**
Подождать окончания окна (15 минут по умолчанию). Параметры — `LOGIN_MAX_FAILURES`
и `LOGIN_WINDOW_MINUTES` в `.env`.

**Как отключить доступ, не удаляя пользователя?**
Сейчас предусмотрено только удаление. Если нужен «мягкий» бан — можно добавить
команду и поле `is_active` уже готово к этому.
